# 需求与验收追踪

需求依据为用户指定的原始《课题三final.pdf》，不是本地其他同名副本。当前范围以 3.2 FPGA 增量编译器为主；3.1 布尔处理器、3.3 全可视验证作为背景，不自动扩大实现范围。

| ID | 能力 | 当前状态 | 验收方式 |
|---|---|---|---|
| R0a | PDF 第一步：网表输入处理与初始分析 | 已完成：用户确认当前阶段范围；基本图、拓扑及用户周期配置已在新导出 opt DCP 上走通 | 当前受支持输入通过完整流程；通用外部宏接口、独立分析入口和全面诊断转为工程完善项 |
| R0b | PDF 第二步：高层次拓扑优化与初始多芯粒预布局 | 部分完成：AMF 有 2.0 基础；独立 non_dataflow_case 已有资源感知划分、多 SLR 区域规划和软 Pblock，尚未接入 AMF；min-cut ILP 及完整时序反馈仍有差距 | 芯粒容量与宏可放置性、跨芯粒连接代价、关键路径反馈、初始分配报告及真实多芯粒验证 |
| R0 | 可复现全量基线 | 历史 benchmark、新导出 faceDetect opt DCP 及同输入 Vivado 原生对照均已完成 | 固定版本与输入，检查路由、DRC、时序、产物哈希；保留已知警告与支持边界 |
| R1 | 规范化网表与物理状态快照 | 待实现 | 保存功能参数、连接、约束、器件/工具版本；拒绝不兼容缓存 |
| R2 | 跨版本匹配与变更分析 | 待实现 | 覆盖无变化、重排、LUT INIT、增删单元、连线与约束变化 |
| R3 | 增量控制器与影响范围 | 待实现 | 明确活动/缓冲/冻结对象；记录依赖失效、扩域和全量回退原因 |
| R4 | 局部布局、打包和合法化 | 待实现 | 冻结位置稳定、资源占用一致、活动区合法，V1 可完成后端实现 |
| R5 | 增量时序与质量反馈 | 待实现 | 正确更新受影响时序图，质量不合格时扩域或回退 |
| R6 | 多芯粒资源分配和 SLL 感知 | 独立前端已有多 SLR 资源分配和真实 case；AMF 器件/区域接口、SLL 容量与延迟模型待实现 | 在真实多芯粒器件上验证容量、跨界连接、拥塞与时序 |
| R7 | Vivado 后端复用与指标 | 全量接口已有；增量复用待实现 | 分别记录 AMF 位置复用、Vivado 复用、阶段及端到端耗时 |
| R8 | 实验评估和交付 | 管理结构已建立 | 同一 V1 的全量/增量对照、消融、失败案例和复现入口 |

说明书未给出 FPGA 3.2 可直接采用的数值验收门槛。不得将布尔处理器部分的加速数字作为本项目承诺。XCVU095 是当前单芯粒基线，不证明多芯粒能力。

第一步的源码与实验评估见 [网表输入处理与初始分析](../research/step-01-netlist-input-assessment.md)。R0a 是原文第一步的工程拆分；R1/R2 是面向后续增量控制器的快照与差异能力，不能因为后者尚未实现就否定现有基础网表读取能力。

第二步逐项证据见 [高层次拓扑优化与初始多芯粒预布局](../research/step-02-topology-floorplanning-assessment.md)。R0b 对应 PDF 第 13-14 页的（2），与 R6 的多芯粒能力有交集，不表示已完成多芯粒算法。当前时钟区域网格和二维预布局不能作为芯粒归属模型的替代。

独立前端的实现、版本边界及复用方案见 [partition / floorplan 与 AMF 接入评估](../research/partition-floorplan-amf-integration-assessment.md)。其多 SLR 能力不能漏记，也不能在尚未集成和验证时记作 AMF 已支持多芯粒。

时序输入约定：以用户给 placer 的约束为准；现有网表提供连接和拓扑，不能自行确定目标周期。DCP/XDC 自动导入为可选扩展，不是 R0a 的必需验收项。分别记录 AMF 的优化目标与 Vivado 后端分析约束。
