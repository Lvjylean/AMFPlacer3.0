# 实验与数据管理

最终 DCP 及大型中间数据保存在服务器，不自动下载到本地，也不提交 Git。许可证保留在账户工具配置位置，不放入本项目。

每次运行产生唯一目录 `experiments/runs/<run-id>/`，至少包含 config、manifest、status、logs、reports。manifest 记录代码提交、未提交修改、输入与二进制哈希、工具版本、参数、开始/结束时间、退出码。构建使用独立源码快照及构建目录。

`experiments/registry.json` 登记运行入口，实际状态读取各运行的 `status.json`；`experiments/baselines/` 记录固定对照结果。成功与失败运行都保留，不能覆盖旧目录来制造连续成功记录。

历史目录已纳入项目时，保留旧路径符号链接，确保旧 manifest、日志和重编译来源中的绝对路径仍有效。历史文件中的原始路径不批量改写。

本地只同步报告、配置、日志和指标。同步器明确过滤扩展名，跳过符号链接、输入和构建目录。历史上已下载的本地 DCP 保留，今后不自动新增副本。

比较规则：同一个修改后的 V1、同一器件与约束、相同线程及工具设置。分别报告 AMF、后端和端到端耗时，记录全量回退成本。评估包括完整性、合法性、setup/hold、DRC、bus skew、移动/复用率，必要时加入功能或网表等价验证。

## Vivado 导入策略（2026-09-30 用户确认）

AMF3 常规完整流程沿用原版允许后端修复的策略：`amf3.py full-run` 默认 `import_policy=repair`。先保存导入审计，再允许 Vivado `place_design` 修复拒绝放置、未放置或位置不一致的单元，并继续 `route_design`；无需先运行一轮严格导入失败实验。`--allow-import-repair` 保留为显式选择及旧命令兼容。

`--strict-import` 是可选诊断：导入审计不满足全部原 LOC/BEL 与合法性要求时，在 `place_design` 前停止。`--import-only` 仍隐含严格模式，成功后结束，不运行完整布局布线；它不能与 `--allow-import-repair` 同用。`--upstream-backend` 继续仅用于已验证的原版 AMF2 构建，不是 AMF3 启用修复的必要选项。

两种策略都记录导入拒绝、各阶段位置差异与保留率。修复策略不等于严格导入通过，不能据此把 `strict_import_verified` 改成 true；完整导出覆盖、设计单元存在性、最终级联合法性、全量路由、DRC 与 setup/hold 检查仍保留。时钟和同步器属性不因启用修复而修改。AMF3 不继承原版导出器遗漏单元的行为。

历史运行的策略和结果保持原样。已按 repair 完成的实验可以沿用，不因这次默认值变更重新执行 AMF 或布局布线。

## 运行时间统计口径（2026-09-28 用户确认）

AMF 实际布局与 Vivado 文件格式适配必须分开，适配不计入 placement。计时默认使用墙钟秒数，CPU 时间另列，不能混用。

- AMF 布局：聚类/SA、QP、扩散、合法化、打包及 BEL 分配等实际布局工作；输入解析、文件导出、诊断输出如有可靠分段，分别记录。
- 格式适配：DCP→AMF 网表导出，以及 AMF→Vivado 结果导出、脚本/文件转换、位置导入；按方向和阶段分项列出。
- Vivado placement 与 routing：分别使用 place_design、route_design 完整调用耗时。routing 包含内部迭代，不将单轮重布线再次累计。
- 工程与验证开销：工具启动、DCP 打开/写出、导入审计（repair/strict 均保留）、报告、边界采样等单列。不能把“总墙钟减去布局布线”的全部余量称为格式适配。
- 同时保留 AMF 进程墙钟和端到端总墙钟；进程墙钟是外层包络，内部导出是其子项，不能重复相加。AMF 进程净时间只扣除有完整起止记录的导出，仍未分段的输入解析、诊断和输出需明确标注，不能称为纯算法耗时。
- 历史数据缺少分段时写“未单独计时”，不能用估值冒充测量。当前 GETRF 完整实验复用网表缓存，本轮 DCP→AMF 导出未执行；首次导出成本另列，不混入本轮 placement，也不能据此宣称完整冷启动成本为零。

现有采集器保留原始 seconds 字段，并在 timing_accounting 中追加有证据的分解。AMF 核心算法独立计时没有完整覆盖时保持空值。报告中的“AMF 运行（扣除已计时 Tcl 导出）”是可追溯的进程净值，不等于严格的纯算法计时。
