# U250 SA 跨 die 纵向补偿：1.415 ns 单点标定

用户2026-11-02接受现有统计值1.415 ns，作为floorplan SA的跨die距离补偿参考，暂不继续扩大样本或拟合完整二维模型。本副本基于698c78453bb77f9c47c488a0a7b64b9d6cdb8192，保留已完成的U250第三列附加罚移除；原VU095/VCU108策略及历史源码不改。

## 标定口径

参考来自GETRF/U250最新已布线DCP的只读统计：两端接近实际Laguna入口/出口（各侧 `|dx|+0.4|dy|≤20`）的211个分支中，同列且相邻CR的130个分支完整SLOW_MAX延迟中位数为1.415 ns。127个分支fanout≤8；这是混合CR内部位置的统计参考，不是全部采用CR中心的实验，更不是固定额外1.415 ns。

证据目录：`experiments/evidence/20261102-sll-statistical-overhead`。输入DCP SHA256：`b67c6f8a1dd15768d6fa1da8926aa49efabc02f2b88ffedea951ca2bcfe6133b`。本次不重新布局、布线或改写原DCP。

当前普通U250时序模型在 `dx=0` 的远距离分支为：

```
F(0,y) = [202.12777470189823 - 131.59702340956898*y^0.3
          + 136.17523346378107*sqrt(y)] / 1000 ns
```

解 `F(0,Yeq)=1.415` 得 `Yeq=182.69021393960458`。这是当前模型的单点反解，不是新统计回归，也没有改动PlacementTimingOptimizer的函数或系数。

## SA代价

```
H = deviceH / gridH
extraY = Yeq - H
cost(s,t) = edgeWeight * (abs(dx) + saY2xRatio * (abs(dy) + Nseams*extraY))
```

当前GETRF普通SA的H为59.9375，extraY为122.75271393960458；原本跨界相邻行已计算的H仍包含在abs(dy)中，仅增加剩余量。总等效行数为3.0475673，净增加2.0475673行；若按实际物理CR间距60比较，总3.0448369行。当前有效SA比例0.32时，每道边界增加39.28087个加权线长单位，再乘连接权重。使用显式其他SA比例时仍按原有效比例缩放。

横向普通距离和原连接权重保持，补偿为纵向加项。它使总代价同时包含横纵距离，但**没有声称重新拟合了随横向位置变化的跨die增量**。1.415 ns作为完整参考段替换一行普通距离，不能再叠加到已经包含接入/接出的细粒度时序模型。

接缝计数来自`DeviceInfo::getSLRBoundaryCount`的实际器件CR/SLR元数据，而不是硬编码每4行或用SLR编号相减。补偿只用于普通CR网格，要求网格行数与真实CR行数一致。固定端点按实际位置映射到CR后执行相同补偿，并保留已有fixed connection factor。完整评价和贪心部分评价一致；同die连接、普通CR边界及重叠罚没有新增代价。

在SA启动前预计算行对和行到固定端点的补偿表，迭代中只读查表；不会在每次评价中调用pow、时序模型或SLL规划。表在多线程solve期间不变。没有修改既有多启动行为。

## 启用和兼容

- 在本独立候选中，普通U250 SA默认启用；`SACrossDieCompensationEnable=false`用于原目标的对照。
- VU095/VCU108默认关闭，既有第三列额外罚及其他行为不变；显式要求使用U250标定会报错，防止误用。
- DFX物理网格路径在普通SA配置前返回，保持原目标；底层API拒绝将两种网格机制混用。
- capability增加`sa_cross_die_compensation_schema=1`，普通SA启动记录参考ns、总等效Y、行距、每道边界额外Y和实际边界数量。
- 原配置文件不改；`SLRBoundaryDelayNs`和虚拟SLL时序模型不改；该SA开关独立于SLL数量/规划开关。
