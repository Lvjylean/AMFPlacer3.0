# MiniMap2 逻辑结构差异与等价性分析

2026 年 10 月 3 日完成对既有 U250 完整设计的只读核验。**在相同初始化、共同 GSR 释放之后、二值且忽略物理延迟的数字模型下，AMF3 后端结果与原生 Vivado 结果均通过相对共同综合输入的逐原语改写检查，可以判定两者逻辑等价。** 未解释的单元差异、额外单元、删除单元、网络映射冲突和顶层端口差异均为 0。

这份结论来自覆盖完整逻辑图的专用检查器，包括受保护 XDMA 模块的原语配置及实际层次连接。没有运行通用 LEC/SEC 形式工具、激励仿真或上板测试；本结论不验证共同输入本身是否正确实现 MiniMap2 算法，也不保证 AMF3 在 8 ns 下可靠运行。

## 差异来源与验证结果

两条流程从相同的 `xcu250-figd2104-2L-e` DCP 出发，均使用 Vivado 2024.2。AMF3 提供的放置结果与 Vivado 原生放置结果不同，后续物理综合选择的驱动复制、缓冲和局部改写也不同。因此最终网表的实例数和网名不必相同。

| 变化 | AMF3 相对输入 | 原生 Vivado 相对输入 | 核验依据 |
|---|---:|---:|---|
| 新增常开 BUFGCE | 45 | 34 | CE 恒为 1、ASYNC 模式及其余参数符合规则，GSR 释放后输出逻辑等于输入 |
| 复制 FDRE | 501 | 243 | 逐个检查初值、反相参数，以及 C、CE、D、R 的等式 |
| DSP 输入寄存器外移 | 2 个 DSP，共 34 个 FDRE | 0 | 每个 DSP 检查全部 30 个 A 输入位及 17 个独立外部寄存器 |
| LUT 功能缩减 | 0 | 112 个替换 | 在已证明的输入等价关系下，穷举真值表核对输出 |
| 跨模块复位重连 | 0 | 2 条新别名，涉及 9 个负载引脚 | 读取实际层次网络段，追到等价 FDPE 驱动并核对状态方程 |

AMF3 新增的 535 个 FDRE 因而分为 501 个复制寄存器和 34 个 DSP 外移寄存器，不是新增 535 级流水线。复制寄存器有相同初值和状态更新方程，其输出逐周期相等，分担不同负载不会改变理想逻辑行为。

### DSP 外移没有增减流水级

AMF3 后端 `place_design` 日志的两条 `[Physopt 32-665]` 分别记录 17 个寄存器从 DSP 移出，汇总记录创建 34 个寄存器。对应两个 DSP48E2 的 `AREG`、`ACASCREG` 从 1 改为 0。

原结构是 A 输入经过 DSP 内部 A 寄存器，再进入 DSP 组合计算；新结构是 A 输入经过外部 FDRE，再进入关闭 A 寄存器的 DSP。检查器确认时钟一致、CE 为 1、R 为 0、INIT 为 0，且 DSP 的输入模式与反相设置符合这条改写规则。两边有效寄存器均满足 `q[n+1] = A[n]`。

每个 DSP 的 30 位 A 端口包含符号扩展，只有 17 个独立输入位，因此每个外移 17 个 FDRE 即可；已逐位核对全部 60 个 A 端口位，没有只凭“34 个寄存器数量吻合”判断。DSP 寄存器推入或移出也是 Vivado 支持的物理优化方式，见 [AMD DSP Register Opt](https://docs.amd.com/r/2024.2-English/ug904-vivado-implementation/DSP-Register-Opt)。

### 原生 Vivado 的 112 个 LUT 替换

原生放置日志记录 `Equivalent Driver Rewiring` 创建 112 个单元、删除 112 个单元，涉及 74 个优化对象。实际网表中的替换分布如下。

| 替换类型 | 数量 |
|---|---:|
| LUT6 → LUT4 | 56 |
| LUT6 → LUT5 | 52 |
| LUT5 → LUT4 | 3 |
| LUT3 → LUT2 | 1 |

相同信号或已证明等价的驱动占用多个 LUT 输入时，输入引脚数可以大于独立布尔变量数。检查器先建立驱动等价关系，再以每个 LUT 的 INIT 和输入连接构造真值表，消除重复变量、常量和无关变量，最后逐项比较。这 112 项全部通过，并且输出网络连接一致；不是只根据 `_comp` 名称或 Vivado 日志接受替换。

### 两条复位别名为什么等价

原生结果把部分 RAM 时钟使能逻辑的复位输入换接到既有复制寄存器，新增跨 `udma_wrapper` 与 `ram_top` 的两个接口别名。仅比较加密模块端口时，这表现为两个模块接口变化；展开到原语后，对应 9 个 LUT 输入连接变化。

例如，输入中的 `ram_top/pwropt_5` 实际连接到 `pcie_dsc_rst_3ff_reg_rep` 的输出；原生中的新别名连接到 `pcie_c2h_rst_3ff_reg[0]_rep__0` 的输出。名字包含不同的 `dsc`、`c2h` 并不直接决定是否等价：本例这些 FDPE 的 INIT 为 1，初值、反相参数及 C、CE、D、PRE 方程经核对相同，因此复位断言与后续采样行为在所述模型中一致。

核验读取了 Vivado 的实际网络段关系，将模块内外的别名合并。每份 DCP 查询 45,687 条相关网络，输入与 AMF3 各得到 53,101 对别名，原生得到 53,109 对。补全这些连接后，9 处剩余差异全部消失。层次网络查询使用 `get_nets -segments`，其用途见 [Vivado 2024.2 get_nets 文档](https://docs.amd.com/r/2024.2-English/ug835-vivado-tcl-commands/get_nets)。

## 覆盖范围与判定方法

先展开公开的功能 Verilog，再通过正常的只读 Vivado Tcl 接口提取两个受保护模块的配置、引脚和层次网络关系。三个 DCP 中均读取 37,225 个受保护区域原语，其中 30 个 GND/VCC 归一化为常量，其余 37,195 个纳入逻辑图。剔除 UNISIM 原语内部的重复实现层次，避免同时比较一个 RAM 原语及其内部实现子单元。未执行解密操作。

| 检查项 | AMF3 对共同输入 | 原生 Vivado 对共同输入 |
|---|---:|---:|
| 参考功能原语 | 716,964 | 716,964 |
| 结果功能原语 | 717,544 | 717,241 |
| 参考原语逐项核验通过 | 716,964 | 716,964 |
| 未解释的结构差异 | 0 | 0 |
| 未解释的新增或删除 | 0 | 0 |
| 网络映射冲突 | 0 | 0 |
| 顶层端口差异 | 0 | 0 |

这些是功能仿真网表的原语计数，不应直接代替 AMF 放置对象或器件利用率统计。两份结果中数量多出的原语均由上表列出的复制、缓冲和 DSP 外移规则解释。共同输入与两份结果的外部端口及 17 个时钟快照也已核对一致。

检查方法依据相同原语函数、相同初始化及相同状态更新方程建立对应关系；LUT 使用穷举真值表，DSP 外移使用安装版本 UNISIM 的寄存器语义。检查器遇到不支持的表达式或不符合规则的改写会拒绝通过。14 项测试全部通过，覆盖错误复制输入、错误初值、动态缓冲使能、错误 DSP 数据位或时钟、错误 LUT 真值表、异步复位不一致，以及层次别名和常量冲突。

这属于可复现的专用结构与状态方程核验；机器报告保留 `full_design_formal_equivalence_proven=false`，明确未声称通用形式验证工具签核。

## 逻辑等价与 8 ns 时序验收

| 最终结果 | WNS | WHS | 当前时序约束 |
|---|---:|---:|---|
| AMF3 加 Vivado 后端 | −5.545 ns | +0.010 ns | 未满足 |
| 原生 Vivado | +0.042 ns | +0.009 ns | 满足 |

核心目标周期为 8 ns，其他参考和派生时钟保持原有约束。逻辑等价结论不会消除 AMF3 的建立时间违例：在真实硬件中，数据可能未能在采样边沿前稳定。因此可以接受“逻辑改写保持功能”的检查结果，当前 AMF3 结果仍不能作为已满足 8 ns 的实现提交。未执行 SDF 仿真或板级功能测试。
