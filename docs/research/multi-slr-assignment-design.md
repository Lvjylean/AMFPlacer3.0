# AMFplacer3.0 多 SLR 分配设计

日期：2026-09-27。状态：**设计草案，尚未实现或实验验证**。本轮研究围绕用户指定的多 SLR 分配策略，保持 AMFplacer3.0 的正式名称和增量编译器总体目标。

依据为 [Xilinx 专利分析](xilinx-slr-partitioning-patent-analysis.md)、[多 die 剩余工作](multi-die-remaining-work.md)、[物理边界实现](device-physical-boundary-implementation.md) 和 [严格导入验收](clb-import-legality.md)。本次已只读核验服务器提交 `d534237b3f1b042a65f9c25721d5bb44c37254fa`。SSH 重复别名导致的解析问题通过临时指定已有 IP 绕过，未修改 SSH 配置。

## 1. 要形成的能力

在全局布局前给出每个可移动分配对象的 SLR 归属；在资源、固定对象和专用级联约束下，减少对关键路径不利的跨界。布局和合法化发现不可放置时，返回具体冲突，修复分配，保存全部变化原因。

```mermaid
flowchart LR
    A[网表、器件、用户时钟约束] --> B[原子对象与允许 SLR 集合]
    B --> C[多资源可行分配]
    C --> D[时序与跨界代价优化]
    D --> E[SLR 内初始布局、全局布局、合法化]
    E --> F[严格导入与 Vivado 验收]
    E -->|容量、宏候选或打包冲突| C
    E -->|STA 与归属变化| D
```

图中 C、D 及分配反馈契约为拟新增能力；E、F 复用现有基础并需增加接口。算法研究先使用 U250 / 原始 GETRF 输入。外部 partition/floorplan 接入、真实 SLL 容量优化和跨版本增量求解保持独立阶段。

## 2. 三种对象不能混为一体

| 对象 | 是否能拆分 | 意义 |
| --- | --- | --- |
| 原子布局对象 | 按已支持的 PU、宏和级联规则决定 | 承载实际合法性，例如需共同放置的 Carry/DSP 级联 |
| 时序分配簇 | 可以撤销或拆分 | 为 SLR 分配临时保护关键连接，不新增物理连续放置要求 |
| 固定对象 / 后续增量冻结对象 | 当前求解中不能迁移 | 保持合法位置和占用；冻结解除需经过明确的扩域流程 |

普通逻辑分组、独立 RAM/DSP 不能仅因为属于同一层次或原始簇就被禁止跨 SLR。专用连接是否允许跨界以端口和器件规则判断。时序簇合并前，必须检查候选 SLR 集合交集和资源需求；不能用一次无界并查集收缩制造无法放入任何 SLR 的巨簇。

## 4. 资源约束与可行性

设活动对象 i 分配到 SLR s 的二元变量为 `x[i,s]`，需求为 `d[i,r]`，容量为 `C[s,r]`。`U[s,r]` 表示预留给禁用、固定、冻结等互不重复类别的占用；禁用项若已从 C 中扣除，就不得再计入 U。

\[
\sum_{s\in A_i}x_{i,s}=1,\qquad
U_{s,r}+\sum_i d_{i,r}x_{i,s}\le C_{s,r}
\]

`A_i` 是由固定约束、器件资源类型和宏候选过滤出的允许集合；集合为空要报告对象及原因。硬容量与软目标利用率分开，超过软目标可以带罚项继续，超过物理容量不得提交结果。

资源至少沿用现有 LUT、FF、SLICEM LUT、CARRY、MUX、DSP、BRAM18/36、URAM 口径。SLICEM LUT 是 LUT 子集，BRAM18/36 共享 18K 槽位；RAMB36 的虚拟辅助占用不能与真实资源重复累计。不同资源类型不能折算成一个 cell 数后声称全部可行。

总量是必要条件，宏的连续列、已占 site、FF 控制集、LUT 共享输入和 BEL 通路仍需检查。对硬宏可先做候选 site/列过滤和匹配可行性检查；容量相同但碎片分布不同的 SLR 不能当作等价。初始化时优先处理候选少、资源稀缺或固定关系强的对象；CLB 总量检查不冒充最终打包证明。

## 5. 跨界统计与时序成本

### 5.1 两套图服务不同用途

通信统计保留超图 net 身份；时序图保留 driver-sink 和内部时序弧。对当前纵向线性 SLR 拓扑，令 `q(v)` 为对象所在 SLR 的物理顺序索引：

\[
H=\sum_n\sum_b I[\min_{v\in n}q(v)\le b<\max_{v\in n}q(v)]
\]

H 是 **net-接缝穿越代理计数**。一个 net 在同一道接缝只计一次；跨三道接缝计三次。它不是实测 SLL 用量，也未描述路由复制、局部可达性或列拥塞。时钟、常量按现有规则另列；无固定 fabric 位置的 OOC 外部端口标记位置未知，不能默认放到 SLR0。

例如，一个 net 从最下方 SLR 驱动上方相邻 SLR 的 100 个负载：连接穿越统计是 100，net-接缝代理是 1，真实使用多少跨界路由资源要由后端采集验证。两种统计都保留，但不能相互替代。

### 5.2 保护切开后变关键的连接

已知基准连接 slack 为 `s[e]`，候选分配相对基准增加的连接延迟为 `Δd[e]`，局部初筛使用：

\[
\widehat{s}'_e=s_e-\Delta d_e,\qquad
v_e=\max(0,-\widehat{s}'_e)
\]

`Δd` 必须是候选与基准模型之差；基准已含 SLR 惩罚时不得再次全额叠加。1.5 ns/SLR 是当前启发式系数，不能当作专利常数、精确实测值或严格物理下界。HPIO 项在候选 region/坐标确定后由同一延迟接口估计，避免重复加罚。

多个边同时移动会改变路径 arrival/required time，因此局部初筛之后要刷新完整的受支持 STA，再决定保留或撤销。没有初始坐标或有效 STA 时，可先用受约束粗布局启动；只得到拓扑层次时必须标为拓扑代理，不能称为数值 slack。

时钟目标继续来自 `ClockPeriod` 和支持的按 driver 配置；不得从网表猜周期，不改变用户时钟来让分配通过。多时钟、例外路径、未知约束要显式记录支持范围；后端 Vivado 的约束来源另记。

### 5.3 路径往返单独计量

对一条受约束数据路径，令各点 SLR 物理索引为 `q0...qm`：

\[
h_p=\sum_j|q_{j+1}-q_j|,\qquad
r_p=h_p-|q_m-q_0|
\]

`h_p` 为连接级接缝穿越总数，`r_p` 为超过起终点直接跨度的穿越数。它是几何诊断量，不是精确延迟。示例路径 `0→1→0` 的 `h=2,r=2`；两次往返穿越是否值得消除仍取决于时序和资源，不将所有折返判为非法。

## 6. 推荐的求解路线

| 路线 | 优点 | 需要处理的问题 |
| --- | --- | --- |
| 递归二分 | 容易复用现有图划分基础，也接近专利示例 | 第一次切分可能锁死后续四 SLR 选择；每层须重新核对容量、固定对象与接缝 |
| 直接四路分配加局部改进 | 显式看见全部 SLR、异构资源和物理距离 | 需要新动作、资源账本和高效增量成本更新 |
| 簇级 / 局部 ILP | 约束清晰，小规模可作为最优性或可行性参照 | 大规模成本与求解时间需控制，时延估计仍是模型 |

工程上建议先采用 **原子对象合法性 + 多资源可行初值 + 四路移动/交换 + 周期性 STA**。现有 PaToH/SA 可提供初值或对照，接口能力需先核验；这条路线不能标成 ILP 已实现。课题中要求的 min-cut ILP 可放在簇级或冲突邻域求解，并单独验收。

为避免一次引入过多变量，第一版先使用固定、显式配置的资源余量；专利的嵌套阈值搜索作为后续消融候选。固定预算版本和专利启发版本应分别标识。

拟定主循环：

1. 从真实器件和当前 PU 状态建立对象、约束与资源账本，检查固定归属和硬宏候选。
2. 生成可行分配初值，保留求解状态；启发式失败记作“未找到可行解”，只有明确证据支持时才记作“已证明不可行”。
3. 在候选域和容量允许范围内，选择簇到其他 SLR 的移动及对象交换；一次事务同时计算移出、移入和预留，禁止临时双计。
4. 按切开后的时序代价尝试形成可撤销的保护簇；遇到多固定归属冲突或超大簇时，释放代价较小的软保护，保留硬约束。
5. 用局部增量代价筛选动作，提交后刷新 STA 和路径穿越，保存最佳可行状态；设置迭代、时间和无改进上限。
6. 进行 SLR 内 region/坐标分配及布局合法化；若失败，返回冲突对象和资源，拆开软簇、交换或重新分配，再有界重试。

建议目标形式为 `J = w_t*T + w_h*H + w_u*U + w_l*L`，其中 T 是支持范围内的非负时序违例代价、H 是接缝穿越代理、U 是超过软资源目标的罚项、L 是几何线长代价。各项归一化和有效权重必须记录。路径往返可先用于解释与候选排序，后续再判断是否需要额外独立罚项，防止重复计权。

专利幂罚项若作为对照，参数要求、阈值跳变和溢出保护需显式实现；生产候选也可比较连续罚项，并将它标为本项目定义。真实 SLL 容量未接入前，配置和摘要不提供伪造的 `SLL utilization %`。

| `src/lib/HiFPlacer/placement/globalPlacement/ClusterPlacer.cc:716` | SA 构造只传 CLB 权重及二维网格等信息，未传逐 SLR 的异构容量；不能直接把网格归属当作 SLR 分配 |
| `src/lib/HiFPlacer/problemSolvers/SAPlacer.cc:20` | 目标为几何距离、固定端点和同格聚集代价，仍有 `gridX == 2` 的特殊项；新模式需核对并改用真实物理模型 |

| `src/lib/HiFPlacer/placement/placementInfo/RegionCapacityTracker.h` | 已有 `cellDemand()`、`fits()`、`reserve()`、`release()`、`assign()`；从 region 汇总到 SLR 时仍要处理无坐标的未分配对象和占用去重 |
| `src/lib/HiFPlacer/placement/placementTiming/BoundaryAwareClusterer.cc:104` | 当前路径聚拢已使用资源账本，可复用其受影响边评估思路；它本身不是全设计初始 SLR 分配器 |

另一个初始化依赖：当前 `setDSPInnerDelay()` 在初始 cluster placement 和一次固定 CLB 全局布局之后调用。若把数值时序优化前移，必须核对硬资源内部延迟及 arrival/required time 是否已初始化，不能仅凭“时序图已创建”就认为初始 STA 已有效。

SLR 分配结果要贯穿硬资源合法化、全局布局、摊开与 CLB 打包。建议采用以下契约：

- 物理固定对象和专用级联约束始终为硬约束。
- 可移动对象的 SLR 归属在一次分配迭代内受约束；布局器需要越界时向分配层请求修复，事务更新账本和归属版本。
- SLR 内 region 可使用现有 X/Y 软目标；区域中心吸引不能替代 site 候选合法性。
- 在纯软引导实验中允许归属变化，但必须报告计划/初始/全局/合法化/最终各阶段的变化率，结果只称为“SLR 引导布局”。

现有时钟区域列搜索回退可以解除内部搜索限制，但不能静默破坏真实固定归属或新引入的 SLR 约束。若要取消一次求解的 SLR 分配并退回现有全量模式，必须显式标记回退和原因，不能继续将结果记作分配约束已满足。

## 8. 从小规模到 GETRF 的验收

| 阶段 | 交付和通过条件 |
| --- | --- |
| A：数据与审计 | 从真实 PU/器件导出需求、容量、固定归属和候选；完整覆盖、共享资源无双计；只生成审计结果 |
| B：可行分配 | 显式输出四 SLR 归属；所有声明的硬容量和候选域满足；固定对象不动；失败有可追溯原因 |
| C：代价优化 | 加入时序/通信代理和移动交换；每个接受动作的账本与成本能重算；STA 后保留最佳可行状态 |
| D：布局闭环 | 全流程归属审计；合法化失败能有界修复；完整 cell 覆盖、严格导入、级联、DRC、布线和时序分别验收 |
| E：增量扩展 | 稳定 V0/V1 匹配后冻结有效对象、预留占用；只在活动区分配，必要时扩域；报告迁移和保留率 |

小型语义案例应覆盖：切开后才变关键的正 slack 边；两个不同固定 SLR 的关键路径；稀缺 URAM；BRAM18/36 共享容量；SLICEM 子集；专用级联与普通独立硬资源的区别；同 net 多扇出；跨两道以上接缝；零容量/空候选域；SLR 标签重排；容量竞争事务；目标等于容量的罚项边界；时序簇拆分；未知端口位置；无变化 V0/V1。小规模可穷举分配作语义参照，验证可行性和计数，不要求启发式每次达到全局最优。

完整 GETRF 至少比较：现有 delay 模式、仅资源分配、资源加通信代理、资源加通信与时序。必要时再比较专利阈值搜索变体。所有组使用同一冻结源码构建、同一输入与时钟、共同数值保护、明确的随机种子和一致后端条件；历史不同构建只作参考。全局默认配置在验收前不变。

每组同时报告逐 SLR 资源峰值、宏可行性、net-接缝计数、关键路径穿越/往返、分配漂移、AMF 与 Vivado WNS/TNS、hold、严格导入/DRC/路由、阶段耗时及回退。资源代理下降不直接等于布线改善；一次 GETRF 成功不直接外推所有器件/设计。最终 DCP 按约定只留服务器。

## 9. 增量阶段的接口预留

未来在 V0/V1 稳定身份匹配完成后，可为已匹配对象加入迁移成本：

\[
J_{reuse}=\sum_{i\in matched}\rho_i I[s_i\ne s_i^{old}]
\]

该项只衡量 SLR 变化；LOC/BEL 保留、路径受影响程度和布线复用仍需分别计量。活动对象按新网表计算资源，冻结对象保留真实占用，删除对象释放资源，约束或缓存不兼容时扩域/回退。尚未建立跨版本匹配前，不启用这一项并声称增量能力完成。
