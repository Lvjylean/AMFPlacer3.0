# 当前 placement 的运行时间优化建议

分析日期：2026-09-28。依据当前服务器源码（HEAD `d534237b` 加现有工作区修改）和 profiling 运行 `getrf-u250-full-20260928-212958-437785`。本次只分析；没有修改服务器算法或启动实验。相关 `.cc` 已核对本地与服务器 SHA-256 一致。

实测 AMF 进程 3558.370 秒，布局功能合计 3430.178 秒。下面的功能预算不是承诺可节省的时间，包含时间也不能与其子函数再次相加。

## 1. 首先优化合法化的二分图匹配

`MinCostBipartiteMatcher::solve()` 调用 251 次，排他墙钟 2144.944 秒。CLB 合法化入口包含时间 2014.513 秒，硬宏合法化入口包含时间 435.822 秒；两者已经包含匹配。优先调查 CLB 合法化的匹配图，同时保留两类调用来源的细分统计。

### 先压缩子图，保持候选边和代价

已确认的实现问题：

- `MinCostBipartiteMatcher.h:59`：每个求解器都分配全图的 `numLeftNodes + numRightNodes + 2` 个节点。
- 同文件 `:81`：每个求解器都连接源点到全部左节点、全部右节点到汇点，虽然实际候选匹配边仅属于该线程分组。
- `MinCostBipartiteMatcher.cc:73`：真实连通分量按编号取模合并到最多 `maxThreadNum` 组，未按节点数、边数或预估求解量均衡负载。
- `MinCostFlow.h:97`：按最短增广路径逐次增广；源到左节点容量为 1，一次成功增广只能增加一个匹配。
- `MinCostFlow.h:171`：每次 SPFA 都按该求解器的全图节点规模初始化距离、前驱、入队计数和标志。

建议分两步：先对现有线程分组做局部节点重编号，只保留其有效左右节点、边及源汇边；再评估按真实连通分量建立任务、按规模调度，小分量成批处理。目标匹配数采用局部左节点数，保留无法满匹配时的部分匹配处理，不将跨分量独立性推广到任意空间区域。

日志只完整打印了 138 组匹配图规模，不能代表全部 251 次调用。其中 83 组的连通分量数超过 8；一个实际例子为 22,508 个左节点、33,711 个右节点、6,504 个连通分量。但没有逐分量规模和耗时，所以尚不能确定最大耗时是否来自一个大分量，不能预言压缩或增加线程的加速倍数。

不得为并行而直接按 SLR/CR 硬切匹配图，这会删除候选边并改变问题。独立连通分量在原候选图上才可独立求解；即便目标保持不变，同代价匹配的选择也可能改变最终布局。

### 然后评估求解内核

候选方案是带势函数的逐次最短路、以 Dijkstra 求解重新赋权后的非负残量边；同时使用连续边存储、反向边下标和复用工作数组。当前每条正反向边分别 `new Edge`，SPFA 每轮重新建立队列和标志，存在内存访问与分配改进空间。

当前正向边代价为 `tcost + 0.01`，反向边为 `-tcost`，不是严格互为相反数。标准最小费用流接口要求反向代价与正向代价匹配，不能直接替换调用后假定代价语义一致。应先冻结候选图，明确 epsilon、部分匹配和同分处理，用小图枚举及独立参考实现核验匹配数与原始总成本。[Boost.Graph 官方说明](https://www.boost.org/doc/libs/latest/libs/graph/doc/html/graph/algorithms/network_flow/successive_shortest_path_nonnegative_weights.html)

现有 profile 没有拆出 SPFA、图初始化、结果回收的独立时间。下一次针对匹配补充阶段计时、左右节点数/边数、分量大小、增广次数和线程任务耗时，再选择内核。

## 2. 减少全量网格刷新

`PlacementInfo::updateElementBinGrid()` 共 334 次，包含重置共 243.542 秒；自身 218.369 秒，重置 25.173 秒。

当前 `PlacementInfo.cc:906` 每次清空全部资源网格，遍历所有 PU/cell 填入资源网格，再遍历一次填入全局 LUT/FF 网格。`PlacementInfo.h:457` 的逐 cell 插入使用 `std::set` 和互斥锁，而此处全量遍历是串行的。

存在具体的重复调用：`ParallelCLBPacker.cc:357` 调用 `setPULocationToPackedSite()`，其内部 `:2585` 已刷新网格；随后满足条件的分支在 `:366` 又刷新，中间主要是统计 fixed PU，未移动位置。

优先合并这种相同状态下的刷新，并拆开 cell 坐标更新、资源计数、邻居索引和重置职责。通过位置、PU 拓扑、资源占用/膨胀系数的版本号管理有效性，批量建立 bin 内容，复用容器存储。单线程专用批量构建可避免逐 cell 上锁，不能直接去掉供其他并行路径使用的锁。

随后再考虑仅维护移动 PU 及其源/目标 bin。现有 `transferCellBinInfo()` 只覆盖部分共享资源网格更新，不代表完整增量维护已经实现。`reset()` 还会更新 shrink ratio、overflow 计数和其他状态，不能把它当成纯清空函数删掉。多种 BEL 资源的首次可用选择有顺序依赖，需要保留分配规则。

## 3. 候选位置只计算一次代价，再选择前 K 个

`MacroLegalizer::findPossibleLegalLocation()` 138 次，共 224.919 秒；`createBipartiteGraph()` 另为 34.875 秒。CLB 候选搜索另为 19.624 秒。

当前 `MacroLegalizer.cc:891` 将全部候选完整排序，然后 `:894` 截断到 K 个；`MacroLegalizer.h:871` 的比较器反复调用 `getHPWLChange()`。其中网络列表以 `auto nets = ...` 按值复制，且部分分支在判定仅使用位移代价之前已经复制了网络列表。建图时还会重新计算保留候选的代价。

建议先为每个候选建立 `{site, cost}`，在位置和网络状态不变的这次候选计算内复用代价；避免只读网络列表复制。再采用 `partial_sort` 或选择前 K 个后排序，代替全部排序。CLB 已有 PU/site 的 HPWL 缓存，不能重复声称完全没有缓存；它仍存在完整排序、映射查找和建图组织的优化空间。

保持相同候选搜索范围、K 值和边界/级联合法性。top-K 的同分候选需要明确规则并验证；直接减小 K 或搜索半径属于布局策略变化，不列为无损加速。跨迭代缓存必须随位置、网络包围盒、权重、宏结构和站点占用变化失效。

## 4. 扩散过程复用线程和临时存储

扩散功能排他墙钟 207.448 秒。`GeneralSpreader.cc:473` 在 PU 数量超过 100 时，每次创建并 join 一组 `std::thread`；本例对应 worker 执行了 15,080 次。`spreadAndPartition()` 递归调用超过 2,341 万次，内部反复创建/释放 SubBox，扩散中还大量使用临时 set/vector。

可采用持久线程池或统一 OpenMP 调度、按工作量设置并行阈值、对象池和复用临时数组。不要同时扩张外层与内层线程而造成过量并发。线程创建本身尚未单独计时，不能把 worker 的计算时间或 207 秒全部解释为线程开销。数据结构改造须保留遍历/同分顺序，或者单独验证 QoR 变化。

## 5. 时序与区域数据按有效期复用

`getSlackThr()` 69 次、43.631 秒；`setPinsLocation()` 204 次、24.457 秒；`RegionCapacityTracker` 从 placement 构造 133 次、14.712 秒。这些是对应功能预算的子项。

可复用 pin 坐标数组，更新移动 cell 的引脚；避免只读 timingNodes 列表复制；在相同位置、时序模型和约束版本下复用网络延迟/阈值统计；区域资源用量按 PU 移动和打包更新。当前区域容量常量本身已经直接来自器件模型，主要重复工作是扫描所有 PU 计算占用，不能将其误诊为反复读取器件库。

cell 坐标和带 offset 的 pin 坐标并不等价，不能直接把某处 STA 边延迟换到另一处代价中而不核对模型。增量 STA、跳过 STA 轮次和跳过合法化轮次的改动风险更高，应后置；原程序已有宏临时锁定条件，后续应细化已有机制，而非假设完全没有复用。

## 6. 减少诊断开销，独立报告收益

`BoundaryAwareClusterer::audit()` 209 次、73.833 秒，主要包括全图跨界统计、端点排序和关键路径回溯。可分离轻量统计与重报告：保留阶段末尾/最终报告，调试模式保留逐轮报告，对同一状态复用统计。

只调整 audit，不关闭 `physical.refresh()`、边界延迟模型或二维聚拢。审计仍有排序等内部状态行为，要核对调用依赖。此项减少的是进程/诊断时间，依据用户统计口径，不计为 57.17 分钟布局功能的加速。

## 实施顺序和验收

1. 冻结本轮参考条件，补匹配内部阶段与图规模统计，建立可独立回放的匹配输入。
2. 先做局部子图压缩、明确的重复网格刷新消除、单次候选代价复用；逐项保留开关。
3. 再做分量调度、top-K、持久线程和内存复用；独立测量每项收益。
4. 最后评估 SPFA 替换、跨迭代热启动、部分合法化/增量 STA。不得从旧匹配直接固定合法单元而声称与完整重求解等价。

每项先检查同一输入图上的匹配数、成本与合法性、缓存与完整重建一致性；然后进行 GETRF 完整 placement 对照和 Vivado 严格导入，比较最终 WNS/TNS、routing 时间、资源/级联合法性和 cell/BEL 覆盖。只比较主程序退出码或 AMF 耗时不够。

性能验收使用不插桩的同优化级别构建，保持输入、配置和线程数一致；profile 用于定位。现有插桩共记录超过 1 亿次作用域调用，细粒度阶段可能受额外开销影响，不能把带插桩基线与不插桩优化版本直接当成公平加速比。

理论敏感性分析：如果匹配这一个功能快 2 倍且其他工作不变，布局功能墙钟从 57.17 分钟降到约 39.29 分钟；快 4 倍则约 30.35 分钟。这不是实测预测。QP 建模与求解总计仅 104.230 秒，当前优化优先级排在上述大项之后。
